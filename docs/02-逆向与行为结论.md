## 12.1 `com.qualcomm.qti.autoregistration`（类名未混淆，最易读）

采集器 `com.qualcomm.qti.service.Data`，以 SharedPreferences 为存储（`DATA_PREFS`、`IMSI_PREFS`、`REGISTERED_PREFS`），共 67 个字段，逐项列出 getter/setter。实际采集项：

| 类别 | 字段 |
|---|---|
| 设备标识 | `IMEI1`、`IMEI2`、`MEID`、`MMEID`、`MACID` |
| 设备信息 | `MANUFACTURE`、`MODEL`、`HWVER`、`SWVER`、`OSVER`、`PNAME` |
| SIM 卡 | `SIM1ICCID`、`SIM2ICCID`、`SIM1LTEIMSI`、`SIM2LTEIMSI`、`SIM1CDMAIMSI`、`SIM2CDMAIMSI`、`SIM1TYPE` |
| 小区 | `CELLID`、`SIM1CELLID`、`SIM2CELLID`、`BID`、`NID`、`SID` |
| 网络 | `ACCESSTYPE`、`NETWORK` |
| 注册状态 | `REGDATE`、`REGVER`、`REGISTERED_ADDRESS`、`SMS_SEND`、`DISABLED`、`STOPED`、`NOSIM_DONE_WIFI` |
| 重试计数 | `COUNTER`、`LCOUNTER`、`SCOUNTER` |

相关类：`RegistrationEntity`（字段 `ctSlotId`、`isManual`、`isRegistered`、`primarySimSlotId`、`rawData`、`reltDesc`）、`RegistrationOverIms`、`SmsSender`、`SmsFilterReceiver`、`ModemDebugService`、`RegistrationTask`、`RegistrationService`、`RegistrationJobService`、`DeviceInfoProvider`、`DeviceInfoPool`。

要点：

- 同时采集 **LTE IMSI 与 CDMA IMSI**，说明覆盖双制式入网场景。
- 采集 `BID`、`NID`、`SID`，为 CDMA 网络的小区/系统标识，可用于基站定位。
- 存在 `SmsSender` 与 `SMS_SEND` 标志，佐证存在**短信通道**的注册路径，不止 HTTP。
- `RegistrationOverIms` 表明还存在 IMS 通道。

## 12.2 `com.qualcomm.qti.qms.service.telemetry`（通用上传通道）

`TelemetryPayloadGenerator` 的字段与方法：

```
方法  generate(Context, byte[], ArrayList<byte[]>, String): int
      generateEncrypted(同上): int
      getPayload(): byte[]
      getJsonPayload(): JSONObject
      byteArrayToMap / mapToByteArray / isValidCborData
字段  mCborTokenList (co.nstant.in.cbor.model.Array)
      mJsonTokenList (org.json.JSONArray)
      MAX_TOKENS_PER_REQUEST / MAX_TELEMETRY_PACKETS_PER_TOKEN
      MAX_AGGREGATED_TELEMETRY_PACKET_SIZE / MAX_CBOR_METADATA_PER_TOKEN
```

投递结构 `DataParams` 只有四个字段：

```java
String packageName;      // 提交方包名
String dataType;         // 数据类型
byte[] data;             // 任意字节
boolean transmitImmediately;
```

要点：

- 载荷编码为 **CBOR**（包内自带 `co.nstant.in.cbor` 全套编解码器），非 JSON。
- 提供 `generateEncrypted` 分支，说明存在加密上传路径。
- 按 token 分片聚合，带多级容量上限，属**批量遥测管道**。
- `DataParams` 仅含「包名 + 类型 + 字节」，自身不含采集逻辑，任何 QTI 组件都可向它投递任意数据。该组件的性质是**上传通道**，而非采集器。

## 12.3 `com.miui.securityadd`（规模最大的包）

类总数 16510，其中可辨认的功能栈：

| 子系统 | 关键类 |
|---|---|
| 多路径加速（VpnService 实现） | `com.android.linkboost.multi.acc.service.LinkBoostService`、`MultipathMobileCore.MultipathService`、`MpAccClient`、`AccPluginManager`、`ProxyManager` |
| 加速相关模型 | `SdkRegisterRequest`、`ActivateDeviceRequest`、`GetConfigRequest`、`NetData`、`MeasureData`、`SummaryInfo`、`PathInfo`、`RemoteAddrInfo`、`AccessPoint`、`OverseaProxy` |
| 加速度量与上报 | `metric.core.MeasureTracker`、`report.SummaryInfoController`、`report.ReportService`、`vendor.TrafficStatsHelper`、`vendor.DTrafficStats`、`acc.PublicIP` |
| 腾讯 SDK（TMSDK） | `tmsdk.common.module.qscanner.QScannerManagerV2`（云查杀）、`tmsdk.common.tcc.SmsChecker*`、`DeepCleanEngine`、`TrafficSmsParser`、`tmsdkobf.*`（约 400 个混淆类） |
| 崩溃与热更新 | `xcrash.XCrash`、`com.tencent.tinker.*` |

要点：

- 该 VpnService 属**多路径加速**（bonding / redundant / fast-switch 三种配置类），功能是同时利用 WiFi 与移动网络提升吞吐与切换速度，非流量中转。
- 但加速模型中出现 `SdkRegisterRequest`、`ActivateDeviceRequest`，说明启用加速时会**向服务端注册/激活设备**。
- 内置**腾讯 TMSDK**（含云查杀、短信校验、深度清理、流量短信解析），这是隐私面被低估的部分：包名「安全组件」下实际封装了第三方安全 SDK。
- 内置 `xcrash` 崩溃上报与 Tinker 热更新。

## 12.4 `com.miui.guardprovider`（AI 通话防诈）

`com.miui.guardprovider.aiguard` 包下：`AiGuardService`、`AlertActivity`、`PermissionRequestActivity`、`f`、`g`、`h`、`i`，以及 `aiguard.service.EncryptedResponse`、`aiguard.service.FeedbackResponse`。

要点：

- 存在 `FeedbackResponse`，对应前文发现的人工反馈通道（误报时上传通话内容）。

## 12.5 `com.xiaomi.security.onetrack`（事件类型已明确）

# 十三、代码级问题清单

对已反编译的组件按风险点定向阅读（硬编码凭据、加密实现、日志输出、上传字段、敏感数据落盘）。以下为读代码得到的具体问题，每条附证据位置。

## 13.1 高危

### P1 `securityadd` 的 `toString()` 输出访问令牌

字面量扫描命中的类输出格式：

```
ThirdPartyAuthInfo{accessToken='
```

`ThirdPartyAuthInfo` 的 `toString()` 直接拼接 `accessToken` 字段。该字符串一旦进入日志（logcat、xcrash 崩溃报告、`milogsdk` 上传通道），令牌即以明文暴露。该包同时声明 `com.xiaomi.milogsdk.PushUploadLogReceiver`，日志具备外传路径。

### P2 `securitycenter` 内嵌明文 API Key

字面量中存在完整 JSON 片段：

```
"api_key":"key_tencent",
```

该字符串位于 dex 中，未做加密或运行时派生。

### P3 `guardprovider` 日志输出密码长度

```
, passwd len=
```

反编译可见该格式化串用于记录密码长度。虽未输出明文，但长度本身属凭据元数据，且该包具备崩溃上报能力（Firebase Crashlytics）。

### P4 `SystemHelper` 上报内容的完整画像（详见 4.4）

单次上报携带双卡 `IMEI1/IMEI2`、`IMSI1/IMSI2`、`ICCID1/ICCID2`、小区识别码 `TAC/CID/PCI`、WiFi `BSSID/RSSI`、`AppInfo`（已安装应用列表）。这组字段组合可完成设备唯一识别、基站与 WiFi 双重定位、安装行为推断。传输为明文 HTTP，body 加密但字段结构固定。

### P5 `autoregistration` 采集范围为同类最广

`com.qualcomm.qti.service.Data` 共 67 字段，同时覆盖 LTE IMSI 与 CDMA IMSI、双卡 CELLID、CDMA 侧 `BID/NID/SID`，并存在 `SmsSender`、`SmsFilterReceiver`、`RegistrationOverIms` 三条通道（短信、IMS、HTTP）。

### P6 `telemetry` 是开放的上传管道

`DataParams` 仅含「包名 + 类型 + 任意字节 + 立即发送标志」。任何具有绑定权限的 QTI 组件都可通过它投递数据，载荷以 CBOR 编码并支持加密。审计该组件无法得出"它采集了什么"，只能得出"它替谁传了东西"。

## 13.2 中危

### P7 `securityadd` 内嵌腾讯 TMSDK

`tmsdk.common.module.qscanner.QScannerManagerV2`（云查杀）、`tmsdk.common.tcc.SmsChecker*`（短信校验）、`DeepCleanEngine`（深度清理）、`TrafficSmsParser`（流量短信解析），另有约 400 个 `tmsdkobf.*` 混淆类。一个名为"安全组件"的 MIUI 预装包，实际承载第三方安全 SDK 的完整能力面。

### P8 `securityadd` 的加速注册携带设备标识

`SdkRegisterRequest` 字段：

```
appId、dataKey、deviceId、gwId、sign、trTcIp、uuid
```

启用 LinkBoost 加速时向服务端注册 `deviceId` 与 `uuid`。配合该包内的高德定位 SDK，注册行为具备与位置关联的条件。

### P9 `guardprovider` 误报反馈上传通话内容

类 `aiguard.service.FeedbackResponse` 与字符串资源共同确认：用户标记误报时，通话内容上传。另有 `aiguard.service.EncryptedResponse` 说明判定结果加密回传。

### P10 `SystemHelper` 的延迟策略

```java
g1.a.b(context, 240000L);   // 开机后 4 分钟
g1.a.d(context, 0x2bf20);   // SIM 就绪后 3 分钟
```

上报刻意错开开机高负载窗口，用户与系统监控不易察觉。

### P11 `securitycenter` 的广告与 OAID 链路

`adv.sec.miui.com` 在 dex 中出现 18 次，路径包括 `game/hoverBall`、`game/popGames`、`game/fast_reply`、`game/pkg`；同时存在 `com.miui.idprovider.ui.GrantPermissionActivity`（`REQUEST_PERMISSIONS_FOR_OAID`）作为 OAID 采集授权入口。安全中心承担广告变现与广告标识采集职能。

# 十四、行为结论

前文的权限表、字段表、端点表回答的是「它具备什么条件」，本章回答「它实际做什么」。结论按对象、触发事件、动作、产出组织。

## 14.1 行为模型

| 对象 | 生命周期 | 触发事件 | 动作 | 产出 |
|---|---|---|---|---|
| SystemHelper | 开机自启，常驻 | `BOOT_COMPLETED`、`SIM_STATE_CHANGED`、`CONNECTIVITY_CHANGE`、定时 alarm | 采集设备画像 → 组装 JSON → 加密 → POST | 本地 prefs（明文 ICCID/经纬度）、`dm.wo.com.cn:18080` 密文 body |
| AutoRegistration | 开机自启，radio 用户 | SIM 就绪、5G/IMS 能力变化、短信到达 | 采集卡与网络标识 → 三通道注册 | `zzhc.vnet.cn:9998` 请求、短信、IMS 消息 |
| QMS Telemetry | 按需拉起 | 其他 QTI 组件投递 `DataParams` | 聚合 → CBOR 编码 → 加密 | `qms.quicinc.com`、AWS 网关 |
| securityadd·LinkBoost | 用户启用加速时 | 加速会话建立 | 向服务端注册设备 → 建立多路径隧道 | 隧道流量、`SdkRegisterRequest`（含 deviceId、uuid） |
| securityadd·TMSDK | 随包常驻 | 病毒扫描、短信校验、深度清理调用 | 云查杀、样本比对 | 腾讯侧服务请求 |
| guardprovider | 随包常驻 | 应用安装/扫描、来电、视频通话 | 本地查杀、AI 防诈推理 | `sec.miui.com` 请求、加密判定结果、误报反馈 |
| securitycenter | system uid 常驻 | 开机、定时、用户操作、第三方调用 | 权限管理、清理、骚扰拦截、广告、OAID、敏感词检测 | 广告域请求、`data.sec.miui.com` 上报、日志 dump |
| onetrack | 开机自启 | `BOOT_COMPLETED`、安全事件 | 采集设备完整性状态 | 交 `com.miui.analytics` / `UploadMisight` |

## 14.2 逐个组件的行为

### SystemHelper（`com.mobiletools.systemhelper`）

定位：**运营商渠道的设备注册客户端**。

开机后不做任何事，先把注册任务挂到 4 分钟后；SIM 卡进入就绪态后，再挂到 3 分钟后。到点时读取双卡 IMEI、IMSI、ICCID，读当前小区 TAC/CID/PCI，读连接的 WiFi 的 BSSID/RSSI/频段，扫描已安装应用列表，把这些组装成一个 JSON，加密成约 1KB 的 body，用明文 HTTP 发往联通 DM 平台的 `/register` 接口，参数里带机型、厂商和签名。

它同时在本地留下痕迹：两张卡的 ICCID 以明文写入 SharedPreferences，一次百度定位的结果（经纬度 + 逆地理到街道）也明文落盘。

用户视角：**全程无提示、无界面、无通知**。系统里看不到它的图标，只有开机后几分钟的一次网络往返。

### AutoRegistration（`com.qualcomm.qti.autoregistration`）

定位：**运营商入网登记客户端**，面向中国电信的自注册平台。

它在 SIM 卡状态变化时启动，把设备与卡的身份交给运营商：两张卡的 IMEI、MEID、MAC、ICCID、LTE IMSI、CDMA IMSI，以及小区标识。送达方式有三条：HTTP 请求打到 `zzhc.vnet.cn`，或通过短信发送，或走 IMS 通道。它记录注册是否成功、重试次数、注册日期。

用户视角：**不可见**。若未注册成功会持续重试，`register_request_count` 归零说明从未成功过。

### QMS Telemetry（`com.qualcomm.qti.qms.service.telemetry`）

定位：**高通组件的公共上传通道**，不是采集器。

它自己没有采集逻辑。别的 QTI 组件把「包名 + 数据类型 + 一段字节」交给它，它把这些数据按 token 分组、用 CBOR 编码、可选加密、分批送出去。它还会向服务端拉取配置（决定采集什么、采多少）。

用户视角：**不可见，也无法从它自身判断被传了什么**。审计它只能得出「谁在用这条管道」，不能得出「传了什么内容」。

### securityadd 的 LinkBoost（`com.android.linkboost.multi`）

定位：**多路径网络加速器**，用 VpnService 实现。

用户开启网络加速时，它向服务端注册设备（带 deviceId、uuid、appId、dataKey、签名），拿到配置后建立隧道，同时利用 WiFi 和移动网络传输并做快速切换。这是手机厂商常见的「双通道加速」功能。

用户视角：加速生效时系统状态栏会出现 VPN 标识，可在设置里看到。**未开启时它不建立任何隧道**（实测系统内无 VPN 配置、无 tun 接口、无相关进程）。

### securityadd 的 TMSDK（`tmsdk.*`）

定位：**腾讯安全能力套件**，嵌在「安全组件」这个包名之下。

提供云查杀、短信校验、深度清理、流量短信解析。它会向腾讯侧服务发起样本比对与规则更新请求。

用户视角：**不可见**。用户以为在用小米的安全组件，实际其中一部分能力来自腾讯。

### guardprovider（`com.miui.guardprovider`）

定位：**查杀引擎 + AI 通话防诈**。

两件事。第一，应用扫描：把应用名与详情上传做云查杀（腾讯引擎），并把加密后的设备 ID 送往腾讯服务器，取回病毒库与白名单。第二，AI 通话防诈：通话或视频通话期间采集音频（必要时采集视频帧），本地或云端判定是否为诈骗、是否为换脸冒充，判定结果加密回传；若用户标记「误报」，这段通话内容会被上传。

用户视角：防诈告警会以通知或弹窗出现，需要用户授予麦克风与录屏权限；**未授权时相关能力不生效**。查杀在后台静默进行。

### securitycenter（`com.miui.securitycenter`）

定位：**系统级总管**，以 `android.uid.system` 身份运行。

它做的事最多：管理应用权限（弹授权框）、清理内存与存储、拦截骚扰短信与电话、隐藏应用、管理应用锁、提供隐私密码、做敏感词检测（本地词表）、做诈骗检测（XSOF）、导出系统日志（`DumpLogProvider`）、采集 OAID（广告标识）、拉取并展示游戏与广告内容（`adv.sec.miui.com`）、预下载游戏资源。它以 system 身份运行，持有清应用数据与强停应用的权限。

用户视角：大部分功能用户会主动使用（清理、权限、拦截）；广告位出现在安全中心界面内；OAID 采集通过专门授权页进行；日志导出与敏感词检测为后台能力，用户不可见。

### onetrack（`com.xiaomi.security.onetrack`）

定位：**设备完整性遥测**。

开机后读取设备安全状态：RPMB 密钥状态、安全启动状态、存储卷（Vold）安全状态、解锁事件、FIDO/IFAA 状态，以及板级 API 级别、VNDK 版本。把这些事件交给 `com.miui.analytics`，另有 `UploadMisight` 通道送至诊断平台。

用户视角：**不可见**。它不碰通讯录、短信、位置、应用列表。

## 14.3 一次开机的实际时序

以设备 A（双卡、有 4G/5G）为例，行为按时间排列：

```
T+0        系统启动
           ├─ SystemHelper 收到 BOOT_COMPLETED，挂起 4 分钟后的注册任务
           ├─ AutoRegistration 随 radio 进程启动，等待 SIM 就绪
           ├─ securitycenter 以 system uid 启动，拉取广告位与配置
           └─ onetrack 收到 BOOT_COMPLETED，采集安全启动/存储卷状态并上报

T+0~30s    第一个 SIM 进入 READY
           ├─ SystemHelper 的 SIMStateReceiver 收到变化，挂起 3 分钟后的任务
           └─ AutoRegistration 触发注册，向 zzhc.vnet.cn 或短信/IMS 通道发送

T+3min     SystemHelper 的 SIM 定时任务到期
           └─ 采集双卡 + 小区 + WiFi + 应用列表，POST 至 dm.wo.com.cn:18080

T+4min     SystemHelper 的开机定时任务到期
           └─ 再发一次，body 与 sign 与上一次不同

此后       网络切换、SIM 插拔、应用安装、来电、视频通话，各自触发对应对象的行为
```

实测印证：手动触发 `GetSignalInfoReceiver` 与 `OnBootReceiver` 后，请求在秒级内发出，两次 body 长度分别为 1056 与 1040 字节，`sign` 不同。这说明延迟是「计划内」而非「来不及」。

## 14.5 总体结论：预装体系的职能分工

这些组件共同构成一套「设备画像 + 运营商登记 + 云端安全 + 广告变现」的预装体系：**SystemHelper 与 AutoRegistration 负责把设备与卡的身份交给运营商，guardprovider 与 securitycenter 负责把设备与应用的信息交给厂商云并承担安全与广告职能，Telemetry 是高通组件的公共上传管道，onetrack 只报设备完整性，catchlog 等四个组件没有联网能力**。其中唯一被实测抓到向外发送完整设备画像的，是 SystemHelper。

## 14.6 结论的证据边界

- 组件行为中，SystemHelper、AutoRegistration、Telemetry、onetrack 的行为有代码级或实测证据支撑。
- guardprovider 与 securityadd 的行为来自字符串资源、manifest 与类结构，**未做动态验证**；其实际触发频率、开关状态、云端下发是否生效均未确认。
- securitycenter 的业务主体（清理、权限管理、骚扰拦截）未逐方法阅读，其行为描述基于 manifest 组件与字符串，粒度较粗。
