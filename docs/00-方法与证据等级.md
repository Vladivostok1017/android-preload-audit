# 方法、判定口径与证据等级

## 一、审计环境

| 项 | 设备 A | 设备 B |
|---|---|---|
| 机型 | Redmi 24117RK2CC（zorn / K80） | Xiaomi M2002J9E（vangogh / 米 10 青春版） |
| 系统 | Android 16 / HyperOS 3.0.307.0.WOKCNXM | Android 12 / MIUI 13.0.7.0.SJVCNXM |
| 安全补丁 | 2026-08-01 | 2022-09-01 |
| Root | KernelSU（`u:r:ksu:s0`） | Magisk（`u:r:magisk:s0`） |
| SIM | 中国电信 46011 + 中国联通 46001（双卡） | 无 |
| 用户 | User 0 | User 0 |

两台设备分属新旧两代系统，一台双卡、一台无卡，用于对照同一组件在 HyperOS 与 MIUI 上的实现差异。

工具链：`adb` 35.0.2、`apktool` 3.0.3、`jadx` 0.7.1（headless，单包线程数 1，堆上限 12 GB）、设备端 `/system/bin/tcpdump`、`capstone`（用于未 strip 的 native 库）。

## 二、审计流程

```
① 盘点       pm list packages / dumpsys package，取得包名、版本、uid、安装路径
② 取样       从 /data/app 或 /vendor 拉取 APK，计算 SHA-256 存档
③ 静态解析   apktool 解析 manifest：权限、组件、exported、sharedUserId
④ 端点提取   dex 正则扫描 URL、域名、上报字段名、字符串常量
⑤ 代码审计   jadx 逐类阅读，从 Receiver / Service / Provider 入口沿调用链下钻
⑥ 动态验证   设备端 tcpdump 抓包，配合 dumpsys alarm 定位定时器，触发后比对流量
⑦ 处置       pm uninstall -k --user 0，观察系统异常与残留进程
⑧ 回归       业务功能验证（通话、短信、应用锁），必要时 install-existing 恢复
```

静态与动态互为校验：静态读出「会上报 ICCID」，动态须取得对应报文；动态无结果不否定静态结论，只说明触发条件未满足。

## 三、证据分级

| 标记 | 定义 | 示例 |
|---|---|---|
| 【实测】 | 设备上实际观察到的输出、报文、命令回显 | `tcpdump` 取得的 POST 报文、`dumpsys` 的定时器、`pm` 回显 |
| 【静态】 | 从 APK 读到的结构、权限、字符串、方法体 | manifest 权限表、反编译出的 JSON 键名 |
| 【推断】 | 由前两者推出、无直接证据的判断 | 由命令值语义反推触发场景 |

文中「未观测到」指抓包窗口内无该组件的对外连接，表征的是观测结果，不表征能力缺失。

## 四、实现约束与已知问题

复现时会遇到以下六项约束，均已在本次审计中处理并记录。

**1. manifest 编码为 UTF-16LE**

部分 MIUI 系统 APK 的 `AndroidManifest.xml` 采用 UTF-16LE 编码。以 UTF-8 正则扫描会得到全零结果，据此得出的结论无效。判断方法为 `file AndroidManifest.xml` 或检查交替出现的 `\x00` 字节。实测同一份 `securitycenter` manifest，UTF-8 扫描命中 0 次，UTF-16 扫描命中 116 次。

**2. `/vendor` 下的 APK 无法直接 pull**

`adb pull` 对 `/vendor/app/...` 返回失败。处理方式为 `su -c "cp <apk> /sdcard/x.apk"`，再 `adb pull /sdcard/x.apk`，最后删除临时文件。

**3. `--user 0` 卸载不终止运行中的进程**

组件从用户空间移除后，已在运行的进程继续存活。实测 `devicestatisticsservice`、`systemhelper_service`、`dmregservice` 均出现过该情况，需 `su -c "kill -9 <pid>"` 收尾。持久化服务在被杀后重试启动约 2 次，因 `SecurityException: Package ... was not found!` 停止。

**4. 卸载后 logcat 出现持续报错**

persistent 服务反复重启会输出 `Package ... was not found`。属预期噪声，重启一次后消失，不影响功能。

**5. `pm` 与 `cmd package` 子命令不等价**

恢复须使用 `cmd package install-existing --user 0 <包名>`；部分版本上 `pm install-existing` 不可用，脚本中做了回退。

**6. Windows 环境下 adb 输出捕获受限**

`StandardOutputEncoding` 仅在输出重定向时可用。可行做法为将循环置于设备端执行，或使用平台工具调用，避免在 PowerShell 中嵌套捕获。

## 五、能力判定口径

判断组件的对外传输能力仅依据两条硬指标，不以权限数量累计计分：

| 指标 | 含义 |
|---|---|
| `android.permission.INTERNET` | 具备该权限才可能自行发包；缺失则只能交由其他进程代为传输 |
| `android.permission.BIND_VPN_SERVICE` | 具备该权限才可能读取其他应用的流量；缺失则仅能观测自身流量 |

仅持 `INTERNET` 的组件，外传上限为其自身采集的数据；持 `BIND_VPN_SERVICE` 的组件理论上可读取全机流量，但须建立 VPN 通道并经用户授权，可通过 `settings get secure always_on_vpn_app` 与 `ip link` 核查实际启用状态。

本次审计中唯一持有 `BIND_VPN_SERVICE` 的组件为 `com.miui.securityadd`（`LinkBoostService`，用途为网络加速），两台设备上均未建立 VPN 通道。
