# 方法与证据等级

## 一、审计环境

| 项 | 设备 A | 设备 B |
|---|---|---|
| 机型 | Redmi 24117RK2CC（zorn / K80） | Xiaomi M2002J9E（vangogh / 米 10 青春版） |
| 系统 | Android 16 / HyperOS 3.0.307.0.WOKCNXM | Android 12 / MIUI 13.0.7.0.SJVCNXM |
| 安全补丁 | 2026-08-01 | 2022-09-01 |
| Root | KernelSU（`u:r:ksu:s0`） | Magisk（`u:r:magisk:s0`） |
| SIM | 中国电信 + 中国联通（双卡） | 未插卡 |
| 用户 | User 0 | User 0 |

两台机器一台是新系统、一台是旧系统，一个双卡一个有卡无卡，用来对照同一组件在不同 MIUI/HyperOS 版本上的行为差异。

工具链：`adb` 35.0.2、`apktool` 3.0.3、`jadx` 0.7.1（headless，单包线程数 1，堆上限 12 GB）、设备端 `/system/bin/tcpdump`、`capstone`（用于未 strip 的 native 库）。

## 二、流程

```
① 盘点       pm list packages / dumpsys package，拿到包名、版本、uid、路径
② 取样       从 /data/app 或 /vendor 拉取 base.apk，计算 SHA-256 存档
③ 静态解析   apktool 解 manifest：权限、组件、exported、sharedUserId
④ 端点提取   dex 正则扫 URL / 域名 / 关键字（实现、密钥、上报字段名）
⑤ 反编译     jadx 逐类读方法体，从入口（Receiver / Service / Provider）沿调用链下钻
⑥ 动态验证   设备端 tcpdump 抓包 + dumpsys alarm 定位定时器，触发后比对流量
⑦ 处置       pm uninstall -k --user 0，观察是否引发系统异常、进程是否仍存活
⑧ 回归       业务功能验证（通话、短信、应用锁），必要时 install-existing 恢复
```

静态与动态互为校验：静态读到「会上报 ICCID」，动态就要抓到含 ICCID 的报文；抓不到不代表不存在，只是没触发。

## 三、证据等级

| 标记 | 含义 | 举例 |
|---|---|---|
| 【实测】 | 设备上实际观察到的输出、报文、命令回显 | `tcpdump` 抓到的 POST 报文、`dumpsys` 的定时器、`pm` 回显 |
| 【静态】 | 从 APK 里读到的结构、权限、字符串、方法体 | manifest 权限表、反编译出的 JSON 键名 |
| 【推断】 | 由前两者推出的行为判断，无直接证据 | 「开关打开时才会启动」这类条件判断 |

报告里凡写「未观测到」，意思是抓包窗口内没有该组件的对外连接，不等于它不会上报——可能只是条件未满足。

## 四、踩过的坑（复现时会遇到）

**1. manifest 是 UTF-16 编码**

部分 MIUI 系统 APK 的 `AndroidManifest.xml` 是 UTF-16LE。用 UTF-8 正则扫会得到全零结果，据此下的结论全部作废。判断方法：`file AndroidManifest.xml`，或直接看有无 `\x00` 交替字节。同一个包用 UTF-8 扫 `securitycenter` 命中 0 次，用 UTF-16 命中 116 次。

**2. `/vendor` 下的 APK 拉不出来**

`adb pull` 对 `/vendor/app/...` 会失败。绕过：先 `su -c "cp <apk> /sdcard/x.apk"`，再 `adb pull /sdcard/x.apk`，最后删掉临时文件。

**3. `--user 0` 卸载不会杀掉运行中的进程**

组件从用户空间移除后，已在跑的进程继续活着（实测 `devicestatisticsservice`、`systemhelper_service`、`dmregservice` 都出现过）。需要 `su -c "kill -9 <pid>"` 收尾。持久化服务会在被杀后重试启动，约 2 次后因 `SecurityException: Package ... was not found!` 停止。

**4. 卸载后系统会报错但不影响使用**

persistent 服务反复重启会在 logcat 刷 `Package ... was not found`。属预期噪声，重启一次即消失。

**5. `pm uninstall` 与 `cmd package uninstall` 不等价**

恢复必须用 `cmd package install-existing --user 0 <包名>`，`pm install-existing` 在部分版本上不可用，脚本里做了回退。

**6. Windows 上抓 adb 输出容易踩编码参数**

`StandardOutputEncoding` 只在重定向时可用。稳妥做法是把循环放到设备端执行，或直接用 MCP/平台工具，不要在 PowerShell 里嵌套捕获。

## 五、能力判定口径

判断一个组件「能不能外传」，只看两条硬指标，不靠权限数量堆砌：

| 指标 | 含义 |
|---|---|
| `android.permission.INTERNET` | 有它才可能自己发包；没有就只能交给别的进程 |
| `android.permission.BIND_VPN_SERVICE` | 有它才可能看到**别人的**流量；没有就只能看自己的 |

只有 `INTERNET` 的组件，最多泄露自己采到的数据；有 `BIND_VPN_SERVICE` 的组件，理论上可读全机流量，但必须建立 VPN 通道且用户授权，可通过 `settings get secure always_on_vpn_app` 与 `ip link` 核查是否真的在用。

本次审计中唯一持有 `BIND_VPN_SERVICE` 的是 `com.miui.securityadd`（`LinkBoostService`，用途为网络加速），两台设备上均未启用过 VPN 通道。

## 七、没有做的事

明确边界，避免读者误以为范围更大：

- 未修改任何分区、未动 AVB / dm-verity、未写开机脚本、未装 Magisk 模块——所有处置都能一键回滚；
- 未尝试绕过任何应用的加密上传体（抓到的是外层明文、内层加密的报文，只分析外层）；
- 未对厂商服务器做任何扫描、探测或访问，抓包只做被动旁路与本地保存；
- 未在其他厂商设备上验证结论，结论适用范围限于报告标注的系统版本。
