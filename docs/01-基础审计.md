## 二、方法

证据分为三类，报告中逐条标注来源。

| 标注 | 含义 |
|---|---|
| 【实测】 | 在设备上直接观测，来源为 tcpdump 抓包、dumpsys、进程与文件实读 |
| 【静态】 | 从 APK 本体解析，来源为 apktool 解出的 AndroidManifest 与 dex 硬编码字符串 |
| 【推断】 | 由上述证据推导，未经直接验证 |

能力判定采用两条硬门槛：

- 应用向外发送数据，必须持有 `android.permission.INTERNET`。
- 应用要在无 root 条件下访问全量流量，必须持有 `android.permission.BIND_VPN_SERVICE` 并建立 VPN 通道，且需用户授权。

流程为：APK 备份并计算 SHA-256，apktool 解析 manifest 获取权限与组件，正则扫描 dex 提取端点，设备端 tcpdump 抓取实际报文，jadx 反编译读取方法体，最后回写验证。

反编译使用 jadx 0.7.1 headless（每包线程数 1，堆上限 12 GB）。对 `com.mobiletools.systemhelper`（549 个类）逐类解析，从广播接收者入口沿调用链下钻至上报数据模型；反编译失败的混淆方法自动回退为 smali 指令序列，两者均作为【静态】证据记录。

## 三、结论

### 3.1 风险总表

| 组件 | 包名 | 外传能力 | 实际外传证据 | 采集范围 | 风险 |
|---|---|---|---|---|---|
| 手机管家 / 安全中心 | `com.miui.securitycenter` | 有 | 未观测到 | 短信、通话记录、联系人、麦克风、OAID、敏感词检测、日志 dump | 高 |
| 系统安全组件 | `com.miui.guardprovider` | 有 | 未观测到 | 应用清单与详情、设备 ID、通话音频、屏幕与视频帧、全盘存储 | 高 |
| SystemHelper | `com.mobiletools.systemhelper` | 有 | **有，抓到完整报文** | SIM ICCID、精确定位与街道级地址、应用列表、信号、WiFi | 高 |
| 安全组件（插件） | `com.miui.securityadd` | 有，含 VpnService | 未观测到 | SMS 收发、摄像头、高德定位采集、热更新 | 高 |
| AutoRegistration | `com.qualcomm.qti.autoregistration` | 有 | 未触发 | IMEI、MEID、IMSI、ICCID、WiFi MAC、系统指纹 | 中高 |
| QMS Telemetry | `com.qualcomm.qti.qms.service.telemetry` | 有 | 未观测到 | MCC、MNC、机型、使用统计 | 中 |
| 安全数据上报服务 | `com.xiaomi.security.onetrack` | 间接 | 无网络权限 | 安全类事件，转交 `com.miui.analytics` | 中 |
| Device Info | `com.qti.qualcomm.deviceinfo` | 取决于版本 | 无 | 本地展示 IMEI、MEID、ICCID | 低 |
| Device Statistics | `com.qualcomm.qti.devicestatisticsservice` | 无 | 无 | 本地统计 | 低 |
| System Helper Service | `com.qualcomm.qti.services.systemhelper` | 无 | 无 | 无网络权限 | 低 |
| Log generator | `com.bsp.catchlog` | 无 | 无 | 本地日志文件 | 低 |

### 3.2 结论条目

1. 11 个组件中，具备联网上报结构的有 6 个：`systemhelper`、`guardprovider`、`securitycenter`、`securityadd`、`autoregistration`、`telemetry`。
2. 有实测报文证据的只有 `com.mobiletools.systemhelper`，其向 `http://dm.wo.com.cn:18080/register` 发出明文 HTTP POST，body 为加密 JSON。
3. 保持默认启用且无 `INTERNET` 权限的有 4 个：`catchlog`、`qti.services.systemhelper`、`devicestatisticsservice`、`deviceinfo`（v16）。删除这些组件不减少网络外传面。
4. 持有 `BIND_VPN_SERVICE` 的只有 `com.miui.securityadd`，服务为 `LinkBoostService`，用途为网络加速。其余 10 个无 VPN 组件。
5. 11 个组件均无 tcpdump、libpcap 或代理类组件，无全量流量采集实现。
6. 系统层存在一个由 init 托管的 tcpdump 守护进程，常驻录制所有接口的报文头，不录制 payload，不向外发送，详见第七节。

### 5.1 数据流向

```

无网络权限     无                                                             catchlog、qti.services.systemhelper、devicestatistics
```

### 5.2 共性问题

1. 明文 HTTP 仍在使用：`SystemHelper` 使用 `http://dm.wo.com.cn:18080`，`autoregistration` 使用 `http://zzhc.vnet.cn:9998`，`securityadd` 的高德采集端点为 `http://`。body 加密不改变端点与元数据可被观测的事实。
2. 第三方能力深度嵌入：`guardprovider` 同时接入安天（AVL）与腾讯引擎，并向第三方云上传应用详情与设备 ID，同时在系统安全组件内嵌 Google Firebase 与 Crashlytics 配置；`securityadd` 集成高德定位 SDK 与腾讯 Tinker 热更新。
3. 命名与实际能力不一致：风险最高的四个组件中，`guardprovider` 应用名为"系统安全组件"，`securityadd` 应用名为"安全组件"，二者持有麦克风、通话音频、录屏、短信、安装应用等能力；`com.mobiletools.systemhelper` 应用名为运营商服务，实际采集 ICCID 与街道级定位。
4. 构建质量：`securitycenter` 与 `securityadd` 的 dex 中残留内网地址；`securityadd` 残留测试音频链接与 `androidx.test` 桩 Activity 并声明为 LAUNCHER。

### 5.3 与"流量转发"判断相关的事实

- 11 个组件中仅 `securityadd` 持有 `BIND_VPN_SERVICE`，其余无 VPN 组件。
- 全部组件的 dex 中无 tcpdump、libpcap、透明代理或流量镜像实现。
- 实测上报行为为低频事件驱动，body 规模为 1 KB 量级，无持续大流量上行。
- 设备 B 的实机状态：`always_on_vpn_app` 为 null，`always_on_vpn_lockdown` 为 null，`/data/system/vpn*` 与 `/data/misc/vpn*` 无文件，`:mpAcc` 进程为 0，网络能力位为 `NOT_VPN`。LinkBoost 的 VPN 通道未启用。

## 六、动态抓包试验

### 6.1 SystemHelper（设备 A）

方法：

1. `cmd package install-existing --user 0 com.mobiletools.systemhelper`，恢复组件，数据不清除。
2. `tcpdump -i any -n -s 1500 -c 20000 -w` 全量抓包。
3. 以 root 向 `com.mobiletools.systemhelper/.control.GetSignalInfoReceiver` 与 `/.control.OnBootReceiver` 发送显式广播。
4. 抓包结束后重新卸载。

结果：首次抓包 100 秒未触发时无相关流量；发送广播后立即出现第 4.4 节的 POST 报文。未触发时组件运行但不发送，说明为事件驱动模型。

### 6.2 安全中心（设备 B）

方法：恢复 `com.miui.securitycenter`，数据不清除；分三轮抓包，合计约 380 秒。

| 轮次 | 时长 | 包数 | 触发动作 | 观测结果 |
|---|---|---|---|---|
| 1 | 110 s | 54 | `monkey` 启动（该应用无 launcher 图标，未启动） | `api.ad.xiaomi.com` 的 DNS 查询 |
| 2 | 120 s | 88 | `am start` 主界面、杀毒页、权限管理页（设备处于锁屏，Activity 未显示） | TLS SNI `tracking.miui.com` |

## 七、系统自带的报文头录制进程

tcpdump 抓包期间观察到一个由 init 托管的常驻进程：

```
进程    /vendor/bin/tcpdump -i any -W 2 -C 2 -s 134 -w /data/vendor/wlan_logs/tcpdump.pcap
父进程  1 (init)
属性    init.svc.tcpdump = running
定义    /vendor/etc/init/hw/init.target.rc
输出    /data/vendor/wlan_logs/tcpdump.pcap0，2 MB × 2 环形缓冲
同目录  cnss_fw_logs_*.txt、host_driver_logs_*.txt，合计约 166 MB
```

技术特征：`-s 134` 仅截取二层、三层与 IP 头，不包含 payload；输出为本地环形文件，无外发路径；属厂商 WLAN 诊断链的一部分。

判定：低。该进程记录报文元数据，不记录内容，不向外传输。

停止方式（可逆）：`su -c 'stop tcpdump'`，恢复 `su -c 'start tcpdump'`。

1. 保持 `com.mobiletools.systemhelper` 的卸载状态，该组件为唯一取得实测外传报文的对象。
2. 不恢复 `com.miui.guardprovider`；若需云查杀功能，关闭「AI 通话防诈」并拒绝麦克风与录屏授权。
3. 确认 `securityadd` 的 LinkBoost VPN 从未授权：检查 `settings get secure always_on_vpn_app`、`dumpsys connectivity`、`/data/system/vpn*`。
4. 若恢复 `com.miui.securitycenter`，确认 `com.miui.riskcontrol`、`com.xiaomi.security.xsof.*`、`com.miui.bugreport.logprovider` 三个 Provider 无第三方调用。
5. 关注 `securityadd` 的 Tinker 补丁目录，热更新可在不经过应用商店的情况下替换代码。
6. 评估 `com.miui.analytics`，其为 onetrack 的实际上报上游。
7. 网络层收敛：对 `sec.miui.com`、`adv.sec.miui.com`、`data.sec.miui.com`、`amap.com`、`zzhc.vnet.cn`、`dm.wo.com.cn`、`qms.quicinc.com` 做 DNS 或防火墙拦截。
8. 系统自带 tcpdump 守护进程按需停止，命令见第七节。
