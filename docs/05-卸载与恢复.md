# 处置、验证与恢复

## 一、处置原则

处置动作统一为 `pm uninstall -k --user 0 <包名>`。

| 参数 | 效果 |
|---|---|
| `--user 0` | 仅对当前用户卸载，系统分区 APK 保持不变 |
| `-k` | 保留应用数据目录 |
| 可逆性 | `cmd package install-existing --user 0 <包名>` 完整恢复，数据保留 |
| OTA | 系统升级不触发校验失败；未修改分区、未变更 AVB、未写开机脚本 |

不执行的操作：分区 remount、dm-verity 变更、Magisk 模块安装、init 脚本写入。

## 四、处置副作用：应用锁

**现象**：移除安全中心后，此前受应用锁保护的应用无法启动。

**成因**：HyperOS 的应用锁由两段实现。拦截判断位于 system_server 的 `miui.security.ISecurityManager`（binder 服务 `security`），验证密码的界面由 `com.miui.securitycenter` 提供。包被移除后，拦截逻辑仍在，验证界面缺失，应用启动被阻断。

**处理顺序**：

```bash
# 1. 恢复安全中心（保留数据）
adb shell su -c "cmd package install-existing --user 0 com.miui.securitycenter"

# 2. 关闭应用锁总开关（shell 无权限，须 root）
adb shell su -c "settings put secure access_control_lock_enabled 0"

# 3. 再次卸载安全中心
adb shell su -c "pm uninstall -k --user 0 com.miui.securitycenter"
```

处理后 `access_control_lock_enabled=0`，`applock_mask_notify` 同步变为 0，表明安全中心服务实时响应该开关。

排查用设置键：`access_control_lock_enabled`、`applock_unlock_mode`、`applock_mask_notify`、`applock_countDownTimer_deadline`、`app_lock_add_account_md5`。

密钥文件位于 `/data/system/`：`access_control.key`、`access_control_keystore.key`、`access_control_password_type.key`。手动删除会导致应用锁状态错乱。

## 五、其他已知影响

| 影响 | 说明 |
|---|---|
| 安全中心入口 | 图标消失，病毒扫描、垃圾清理、流量监控、骚扰拦截不可用 |
| 系统设置跳转 | 指向安全中心的入口点击无响应，不触发崩溃 |
| 联动功能 | 依赖安全中心的手游加速、网络助手失效 |
| 通信业务 | 移除运营商自注册组件后，`dumpsys telephony.registry` 中 `mServiceState` 仍为 `IN_SERVICE`，通话、短信、数据业务正常 |
| 进程残留 | 卸载后残留进程需 `su -c "kill -9 <pid>"`；持久化服务重试约 2 次后因 `SecurityException: Package ... was not found!` 停止 |

## 六、验证方法

```bash
# 是否仍在用户空间（卸载后应无输出）
adb shell pm list packages --user 0 | grep -E 'securitycenter|guardprovider|systemhelper'

# 是否可恢复（卸载后应仍可见）
adb shell pm list packages -u --user 0 | grep securitycenter

# 进程是否存活
adb shell ps -A | grep -E 'securitycenter|guardprovider|dmregservice'

# 系统分区原件是否完好
adb shell ls -l /system/priv-app/SecurityCenter /product/priv-app/MIUISecurityCenter 2>/dev/null

# 业务状态
adb shell dumpsys telephony.registry | grep -i mServiceState
adb shell settings get secure always_on_vpn_app
```

## 七、恢复方法

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\restore-security-packages.ps1 -Serial <设备序列号>
```

脚本对 12 个包依次执行 `install-existing`。本机不存在的包由系统返回 `Package ... doesn't exist`，无副作用，脚本可在同类设备上重复使用。恢复后建议重启一次，使 system_server 重新初始化依赖。

单条恢复：

```bash
adb shell su -c "cmd package install-existing --user 0 com.miui.securitycenter"
```

## 八、处置顺序

1. 全量备份 APK 并计算 SHA-256（对应 [`evidence/apk-sha256.txt`](../evidence/apk-sha256.txt)）；
2. 先处置无网络能力的组件（`catchlog`、`qti.services.systemhelper`），观察一个完整使用周期；
3. 再处置运营商组件（`systemhelper`、`dmregservice`、`registration`），每次处置后验证通话与数据业务；
4. 最后处置安全栈（`securitycenter` 一族），处置前先关闭应用锁总开关，避免卡在验证界面；
5. 每步保存 `pm list packages -u --user 0` 输出，作为恢复依据。
