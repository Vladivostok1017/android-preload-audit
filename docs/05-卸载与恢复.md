# 卸载与恢复

## 一、处置原则

只做一件事：`pm uninstall -k --user 0 <包名>`。

| 特性 | 效果 |
|---|---|
| `--user 0` | 只对当前用户卸载，系统分区 APK 原封不动 |
| `-k` | 保留应用数据目录 |
| 可逆性 | `cmd package install-existing --user 0 <包名>` 原样恢复，数据还在 |
| OTA | 系统升级不会因此校验失败，不改分区、不动 AVB、不写开机脚本 |

不做的：不改 dm-verity、不 remount 系统分区、不装 Magisk 模块、不写 init 脚本。

## 四、踩到的坑：应用锁

**现象**：卸载安全中心后，之前被应用锁保护的应用全部打不开。

**原因**：HyperOS 的应用锁由两段组成——拦截判断在 system_server 的 `miui.security.ISecurityManager`（binder 服务 `security`），而**验证密码的界面由 `com.miui.securitycenter` 提供**。包没了，拦截还在，界面不在，应用就卡住。

**处理**（顺序不能反）：

```bash
# 1. 先恢复安全中心（保留数据）
adb shell su -c "cmd package install-existing --user 0 com.miui.securitycenter"

# 2. 关掉应用锁总开关（shell 改不动，必须 root）
adb shell su -c "settings put secure access_control_lock_enabled 0"

# 3. 再卸载安全中心
adb shell su -c "pm uninstall -k --user 0 com.miui.securitycenter"
```

处理后 `access_control_lock_enabled=0`，`applock_mask_notify` 同步变 0，说明安全中心服务会实时响应这个开关。

排查用的设置键：`access_control_lock_enabled`、`applock_unlock_mode`、`applock_mask_notify`、`applock_countDownTimer_deadline`、`app_lock_add_account_md5`。

密钥文件在 `/data/system/`：`access_control.key`、`access_control_keystore.key`、`access_control_password_type.key`——不要手删，会导致应用锁状态错乱。

## 五、其他已知影响

- 安全中心图标消失，病毒扫描、垃圾清理、流量监控、骚扰拦截入口不可用；
- 设置里跳转安全中心的入口点了没反应（不会崩）；
- 依赖安全中心的手游加速 / 网络助手联动失效；
- 电信、联通两网的自注册组件被移除后，`dumpsys telephony.registry` 中 `mServiceState` 仍为 `IN_SERVICE`，通话、短信、数据业务正常；
- 卸载后残留进程需手动清理：`su -c "kill -9 <pid>"`。持久化服务会重试约 2 次，因 `SecurityException: Package ... was not found!` 自行停止。

## 六、验证方法

```bash
# 是否还在用户空间（卸载后应查不到）
adb shell pm list packages --user 0 | grep -E 'securitycenter|guardprovider|systemhelper'

# 是否可恢复（卸载后仍应能查到，带 -u）
adb shell pm list packages -u --user 0 | grep securitycenter

# 进程是否还在跑
adb shell ps -A | grep -E 'securitycenter|guardprovider|dmregservice'

# 系统分区原件是否完好
adb shell ls -l /system/priv-app/SecurityCenter /product/priv-app/MIUISecurityCenter 2>/dev/null

# 业务是否正常
adb shell dumpsys telephony.registry | grep -i mServiceState
adb shell settings get secure always_on_vpn_app
```

## 七、一键恢复

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\restore-security-packages.ps1 -Serial <设备序列号>
```

脚本对 12 个包逐个执行 `install-existing`，本机不存在的包由系统直接回一句 `Package ... doesn't exist`，无害，可复用在同一台机器上。恢复后建议重启一次，让 system_server 重新初始化依赖。

单条恢复：

```bash
adb shell su -c "cmd package install-existing --user 0 com.miui.securitycenter"
```

## 八、从头复现时建议的顺序

1. 先全量备份 APK 并算 SHA-256（`evidence/apk-sha256.txt` 就是这套哈希）；
2. 先卸载风险最低的（`catchlog`、`qti.services.systemhelper`），观察一晚；
3. 再卸运营商组件（`systemhelper`、`dmregservice`、`registration`），每次都验证通话与数据业务；
4. 最后动安全栈（`securitycenter` 一族），动之前先关应用锁总开关，避免卡在验证界面；
5. 每步都记一条 `pm list packages -u --user 0` 的输出，恢复时不需要回忆。
